# あめぞう風掲示板 PHP 版 (ファイルベース)

Python 版 (`amezo.py` / `dai.py`) の PHP 移植。スレッドは今までどおり静的 HTML で、投稿のときだけ PHP が動く。PHP 8.1 以上。

## ファイル

| ファイル | 役割 |
|---|---|
| `lib.php` | 共通部品 (エスケープ、文字数、鍵、トリップ、ID、ハッシュ、index 再生成、過去ログ) |
| `amezo.php` | 投稿の受付 (`/amezo.cgi` もここに向く) |
| `dai.php` | 板一覧 (`/dai.cgi` もここに向く) |
| `jump.php` | 外部サイトへの中継ページ (`/jump.cgi` もここに向く)。署名つきの URL だけを表示する |
| `admin.php` | 管理画面 (`/admin.cgi` もここに向く): レス削除、スレッドの非表示・復元 |
| `router.php` | `php -S` 用。許可リスト方式で静的ファイルを配る |
| `hide.js` | ID / トリップの非表示 (ブラウザの localStorage だけで動く) |
| `setup_expose.py` | Colab 用の起動スクリプト (PHP の導入、板フォルダ作成、`php -S`、Cloudflare Tunnel での公開) |
| `config.sample.ini` | 設定の見本。`config.ini` にコピーして、変えたい行だけ有効にする (実行されない形式) |
| `run.sh` | ローカル用 (板フォルダを作って `php -S` を起動。`PORT` `WORKERS` で変更可) |
| `tests/` | Python 版との突き合わせ、結合テスト、メモリ測定 |

## 動かす

### Colab (setup_expose.py)

```python
%cd /content/amezo-php                                  # このフォルダを置いた場所
!python3 setup_expose.py --make-hash 合言葉              # 管理画面のパスワードを delpass.txt に作る (最初の1回)
!python3 setup_expose.py                                 # 起動。表示された https://….trycloudflare.com/ が公開URL
```

起動のたびに、PHP 8.1 以上と mbstring が無ければ apt で入れ、古い php / cloudflared を止め、`blist.txt` の板フォルダを作り、`php -S router.php` と Cloudflare Tunnel を起動する。
起動直後に自己チェックを出す (板一覧は 200、`trip_secret.txt` `delpass.txt` `lib.php` などは 404 になっていること)。
停止はセルの停止 (または Ctrl+C)。

- **置き場所はローカルディスク (`/content` など) にする。** Google Drive のマウント上では `flock` が効かないことがあり、起動時に警告を出す。
  Colab のディスクはセッションが切れると消えるので、`trip_secret.txt` `id_secret.txt` と板フォルダは必要に応じて Drive にコピーしておく。
  鍵が消えると、全員のトリップと ID が変わる。
- 接続元の IP は、Cloudflare が付ける `CF-Connecting-IP` から取る (`127.0.0.1` からの接続のときだけ信用する)。
- `--no-tunnel` でローカルだけ、`--port` `--workers` `--verbose` で調整できる。メモリを節約するなら `--detach` (上の「メモリ」を参照)。

### ローカル (run.sh)

```sh
sh run.sh                 # http://127.0.0.1:8000/
```

## メモリ

測定は Ubuntu 24.04 / PHP 8.3 / `php -S`、数値は PSS (共有ページを二重に数えない値)。Colab (PHP 8.1) では多少違う。

| 構成 | PHP の合計 |
|---|---|
| 通常 (`--no-trim`) ワーカー1 / 2 / 4 | 21.3 / 23.4 / 25.3 MB |
| 拡張を絞る (既定) ワーカー1 / 2 / 4 | 15.9 / 18.5 / 20.2 MB |
| Python ランチャー (`setup_expose.py` の常駐) | 約 19 MB → `--detach` で 0 |

- 大きいのは PHP の土台そのもの。ワーカーは `fork` で土台を共有するので、1つ増えても +1〜2MB ほど (ワーカーを減らしても、あまり減らない)。
- `setup_expose.py` は既定で php.ini を読まず、mbstring と ctype だけを読み込む (約5MB減)。必要な関数が欠けるときは通常の起動に戻る。`--no-trim` で無効にできる。`memory_limit=32M` も付く。
- `--detach` を付けると、起動できた時点でランチャーは終了し、PHP とトンネルだけが残る (ログは `php.log` / `cloudflared.log`、止めるのは `pkill -x php; pkill -x cloudflared`)。
- スクリプト自身のメモリは小さい: 200スレッドの板の再生成が 0.7MB。5.5MB のスレッドへの投稿も `memory_limit=3M` で動く。
  古いスレッド (`o*.html`) が5万本たまった板でも、再生成 0.15〜0.6MB・ページ送りの確認 0MB (ファイル名を配列に溜めず、過去ログ一覧は末尾から1行ずつ読む)。
  過去ログ一覧が無いときの作り直しだけ 9.6MB かかる (1回だけ)。管理画面のスレッド一覧も同じ板で 0.09MB、NG ワードは `ng.txt` を1行ずつ読む。
- 表示中のスレッド一覧は、並べ替えのために全件の名前と更新日時を持つ。既定の `MAX_THREADS=200` なら 0.14MB だが、
  `MAX_THREADS=0` (退避しない) で10万本にすると 65MB かかる。退避しない運用をするなら、上位だけを残しながら読む形に直す余地がある (`tests/mem_plan.php` に試作)。
- 文字列の連結 (`.=`) を配列 + `implode` に変えても、メモリは減らない (20万片で 9.0MB → 16.0MB)。`regen_index` は文字列に溜めず、`fwrite` で書き出している。
- cloudflared のメモリは測っていない。

## セキュリティ (webshell 対策)

webshell = 攻撃者が置いた(または書き込ませた) PHP を、あとから実行される形で残すこと。このアプリでは、次の層で防いでいる。

**1. 置かせない (入口)**
- ファイルのアップロード機能が無い。`eval` `system` `exec` `unserialize` `include` (変数のパス) など、コード実行につながる関数をアプリ本体で使っていない (走査で確認)。
- ファイルを書く・消す・名前を変える操作のパスは、`blist.txt` に載っている板名、数字だけのスレッド番号、定数だけから作る。攻撃者が名前を選べる書き込みは無い。
- 投稿の全フィールド (名前・メール・題名・本文) は、保存前にエスケープする。`<?php` `<?=` `<%` `<script language="php">` は文字になる (`.html` を PHP として処理する設定ミスがあっても実行されない)。

**2. 置かれても実行させない・秘密を配らない (配信の入口: `router.php`)**
- 実行するのは `/amezo` `/dai` `/admin` `/jump` の `.cgi` / `.php` だけ。静的ファイルは許可リスト (`index.html` `数字.html` `o数字.html` `kako.html` `style.css` `hide.js` `ad.html`) だけ。ほかは 404。
- 板フォルダに `shell.php` `.phtml` `.php5` `.phar` `.htaccess` を置かれても 404。許可リストの `.html` に PHP のコードが入っていても、文字のまま返る (実行されない)。
- **`//` で許可リストをすり抜けられる不具合を直した (旧 router)**: `parse_url('//delpass.txt')` は「ホスト名 delpass.txt」と読んでパスが null になり、router は `/` (許可リスト内) と判断して `return false` するのに、
  組み込みサーバーは生の `//delpass.txt` を実際のファイルとして開いていた。**アプリのフォルダ直下の全部のファイルが対象だった**: `delpass.txt`、`trip_secret.txt` `id_secret.txt` `key_secret.txt` `jump_secret.txt`、`cap.txt` `ng.txt` `blist.txt` などがそのまま読め、`.php` は実行もされた
  (板フォルダの中 (`//adm/keys.txt` など) は影響なし)。旧 router を、外から届く形で動かしていたなら、これらを読まれた可能性がある。管理用パスワード・キャップのパスワード・各 `*_secret.txt` を作り直すこと (作り直すと、トリップ・ID・中継リンク・発行済みの認証キーは変わる、または使えなくなる)。
  いまは `parse_url` を使わず、`//`、`%`、`\`、`.` `..` の区間、NUL、`/` で始まらない形 (`http://…`) を 400 で止める。本来の経路は、どれもこれらを使わない。
  `tests/webshell_test.py` が、この種の経路と、秘密ファイル (`//delpass.txt` `//trip_secret.txt` など) を毎回確かめる。
- `%` を含むパスは 400 になる。**板のフォルダ名は ASCII にすること** (非 ASCII の名前は、ブラウザが `%E6…` に変換するため開けなくなる)。板のタイトル (`blist.txt` の3列目) は日本語でよい。

**3. 実行されても被害を小さくする (PHP の起動オプション。`setup_expose.py` が既定で付ける)**
`php -S` の起動に、次を付けても、アプリの全テストが通ることを確認した。コードを実行できた攻撃者が、コマンド実行・外への接続・アプリの外のファイルの読み書きをできなくなる。

```
php -n -d extension=<mbstring.so> -d extension=<ctype.so> -d memory_limit=32M -d expose_php=0 \
    -d allow_url_fopen=0 -d allow_url_include=0 -d open_basedir=<アプリのフォルダ>:/tmp \
    -d disable_functions=exec,passthru,shell_exec,system,proc_open,popen,pcntl_exec,dl,mail,show_source,highlight_file,phpinfo,\
posix_kill,posix_setuid,posix_setgid,posix_mkfifo,symlink,link,putenv,fsockopen,pfsockopen,stream_socket_client,\
stream_socket_server,stream_socket_pair,socket_create,socket_create_listen,curl_exec,curl_multi_exec,proc_nice,proc_terminate,proc_get_status \
    -S 127.0.0.1:8000 router.php
```

`setup_expose.py` は、この制限と、拡張の絞り込み (`-n` + mbstring/ctype) を **既定で付けて** `php -S` を起動する。
起動前に、アプリのフォルダで `lib.php` を読み込む自己テストを、候補ごとに実行し、動く最初のものを使う (絞る + 制限 → 制限だけ → 絞るだけ → なし の順。セキュリティの制限を、メモリの節約より優先して残す)。
一時フォルダは `TMPDIR` で変わるので、PHP に聞いた場所を `open_basedir` に含める (含めないと `tmpfile()` が使えず、管理画面の削除が壊れる)。
`--no-harden` で制限なし、`--no-trim` で拡張を絞らない起動にできる (動かないときの切り分け用)。`run.sh` で起動するときは、上のオプションを自分で付ける。
`disable_functions` は、PHP の中から呼ぶ関数だけを無効にする。`setup_expose.py` が PHP を起動するのは Python の `subprocess` なので、影響を受けない。

**4. 見つける・気づく**
- 板フォルダに置かれるファイル名は決まっている (`数字.html`、`x数字.html`、`o数字.html`、`数字.lock`、`index数字.html`、`kako.html`、`kako.txt`、`keys.txt`、`keys.lock`、`lasttime.txt`、`regen.lock`)。これ以外のファイルがあれば異常。
  板の `.html` / `.txt` に生の `<?` や `<%` があれば異常 (エスケープ済みなので、正常なら入らない)。コードのハッシュを控えておけば、書き換えも分かる。

**まだ弱いところ**
- (直した) `lib.php` は、以前は `config.php` を自動で `require` していた。アプリのフォルダは PHP が書き込める場所なので、書き込みの穴が見つかったときの足がかりになりうるため、実行されない `config.ini` に変えた。キー・型・範囲・文字種を検査して、外れた値は無視する (下の「設定」)。`config.php` は読み込まない。
- Colab では PHP が root で動き、コードと同じフォルダに鍵やデータが書かれる。コードを読み取り専用にする、データのフォルダを分ける、非 root で動かす、Google ドライブを同じランタイムにマウントしない、が望ましい。
- `setup_expose.py` が取得する `cloudflared` は、チェックサムを確かめていない。

## 設定

`config.sample.ini` を `config.ini` にコピーして、変えたい行のコメント (`;`) を外す。`config.ini` は PHP として実行されない形式で、`.gitignore` 済み。
許可リストにあるキーだけを、型・範囲・文字種を検査して使う (外れた値、不明なキー、構文エラーは無視して既定値のまま。理由は `error_log` に出る)。
値の中の `${…}` や定数名は展開しない (`INI_SCANNER_RAW`)。トリップ・ID・キーの計算に関わる値 (`TRIP_CTX` など、公開後に変えてはいけないもの) は、設定ファイルからは変えられない。
古い `config.php` は読み込まれない (あれば、ログに「`config.ini` に移してください」と出る)。

公開後に変えてはいけない値は `lib.php` の `const` に分けてある: `TRIP_CTX` `ID_CTX` `TRIP_LEN` `ID_LEN` `TRIP_PASS_MAX`。
`TRIP_CTX = ''` のあいだは、同じ `trip_secret.txt` を使えば Python 版と同じトリップが出る。

## 管理画面

```sh
php amezo.php --make-hash 'パスワード' > delpass.txt     # 管理用パスワードを作る (Python 版の delpass.txt もそのまま使える)
```

`http://…/admin.cgi` を開いて、板 → スレッド → レスの順にたどる。認証は Python 版と同じで、各画面のフォームにパスワードを持たせて毎回照合する
(クッキーなし)。5回失敗したら、同じ接続元を15分間拒否する (接続元は鍵つきハッシュで数え、`admin_fail.mem` に IP は残さない)。
パスワードがフォームの hidden 欄に入るので、必ず HTTPS (cloudflared 経由など) で使うこと。

- 1番のレスは削除できない (スレッドごと消すときは「非表示」)。削除したあと、スレッドの更新日時は「残った最後のレスの日時」に戻す。
- 非表示は `x数字.html` にリネーム (権限 0600、配信されない)。復元で戻せる。
- レス一覧に ID の列を足してある (荒らしの見分け用)。
- スレッドごとの鍵 (認証キー) の管理は、次の「鍵つきスレッド」を参照。

## 外部リンクの中継ページ

投稿された URL は、直接ではなく中継ページを経由するリンクになる。「このリンク先へ行きますか?」と確認させるためのページで、広告枠を置ける。

```
スレッド HTML:  <a href="../jump.cgi?u=<URL (base64url)>&s=<署名>">元の URL の文字</a>
  → 中継ページ: 移動先のホスト名 + URL 全体を文字で表示 + 「進む」「戻る」(自動では転送しない)
  → 「進む」を押したときだけ、外部サイトへ
```

- **署名つき**: `s` は `HMAC-SHA256(jump_secret.txt の鍵, 'jump:' + URL)` の先頭132bit。署名が合うもの (= この掲示板に実際に投稿された URL) だけを表示する。
  署名がなければ「どんな URL へも飛ばせる踏み台」になり、フィッシングに使われる。`u` や `s` を1文字変えても、別の URL に替えても、ランダムな署名でも通らない (テストで確認)。
- **署名の鍵は、作り直さない**: `jump_secret.txt` を失うと、投稿済みの中継リンクが全部開けなくなる (トリップや ID の鍵より重い)。バックアップに入れること。
  署名が合わないときは、「進む」を出さず、URL を文字だけで見せる (クリックできるリンクにはしない)。
- **中継ページの安全対策**: `http` / `https` で、ホスト名が英数字で始まる ASCII の URL だけ (2000文字まで)。`xn--` を含むドメインには注意を出す。
  `noindex`、`no-referrer`、`no-store`、CSP (nonce つきのスクリプトだけ、他サイトに埋め込めない)。
- **広告枠**: `ad.html` を置くと、中継ページに「広告」ラベルつきの iframe で出る。`sandbox="allow-scripts allow-popups"` (`allow-same-origin` なし) なので、広告のコードは掲示板のデータに触れない。
  `ad.html` が無ければ何も出ない。広告サービスの規約 (中継ページへの設置など) は、使う前に確認すること。
- 直リンクに戻すときは、`config.ini` に `JUMP_ENABLED = false`。
- 既存のスレッド (中継を入れる前の投稿) の直リンクは、書き換えていない。

## 鍵つきスレッド (認証キー)

スレッドを「認証キーがないと書き込めない」にできる。読むのは誰でもできる。**既定は鍵なし**で、管理者があとからでも鍵をかけられる。

管理画面 (`/admin.cgi`) → 板 → スレッド一覧の「鍵の管理」:

- **鍵をかける / 外す**: 鍵つきのスレッドには、返信フォームに「🔒 認証キー」の欄が出る (スレッドの末尾の返信フォームを差し替え、板の index も作り直す)。外すと元に戻る。
- **キーを発行する**: ラベル (誰に渡すか) と範囲を選ぶ。範囲は「このスレッドだけ」か「この板の鍵つきスレッドどれでも」。
  キーは `ABCD-EFGH-IJKL-MNOP-QRST-UVWX` の形 (120bit のランダム値) で、**発行した画面に1度だけ**出る。サーバーにはハッシュしか残らない。
  鍵をかける前に発行しても、あとから発行してもよい。
- **失効する**: キーごとに取り消せる。ほかのキーには影響しない。

仕組み:

- 鍵つきの印は `板/<スレ番号>.lock` (空のファイル)。キーの一覧は `板/keys.txt` (ID、ラベル、HMAC、範囲、発行日時、状態)。どちらも配信されない (許可リスト)。
- キーのハッシュは `key_secret.txt` の鍵つき HMAC-SHA256 (トリップ・ID とは別の鍵)。この鍵を失うと、発行済みのキーは全部使えなくなる。
- 投稿のとき、`amezo.php` は**スレッドのファイルロックの中で**鍵の有無を確認する。管理者が鍵をかけ外しする操作も同じロックの中で行うので、「フォームには欄が無いのに鍵つき」のようなずれは起きない (60件の同時投稿 + 鍵のかけ外し12回で確認)。
- 照合に失敗したときの文言は2種類だけ (「キーが必要」と「キーが正しくありません」)。失効・範囲外・存在しない、は区別しない。
  キーは推測できない長さなので、失敗回数の制限は付けていない。
- キーは大文字小文字・ハイフン・空白の違いを問わない。鍵なしのスレッドに付いたキーは無視される。
- スレッドが過去ログに退避されるときは、`.lock` も消す。
- 鍵つきのスレッドの返信フォームは古いページに残っていることがある。そのときは「ページを再読み込みして」と案内する。

## 鍵

- `trip_secret.txt` と `id_secret.txt` は別ファイル。初回の投稿で自動作成 (`fopen('x')` で排他的に作る)。権限は 0600。
- 鍵ファイルを置く場所や作り方を変えても、鍵のバイト列が同じならトリップ・ID は変わらない。
- ID = HMAC(ID鍵, `id:` + IP + 日付(日本時間) + 板名) の先頭8文字。IPv6 は上位64bitでまとめる。IP は保存しない。
  `global.mem` (新規スレッドの連続制限) も IP ではなく鍵つきハッシュで保存する。

## Python 版との違い

- 日時・スレッド番号は日本時間 (Python 版はサーバーの時刻)。
- 二重カキコの判定が1レス目にも効く。
- NG ワードは HTML エスケープして照合する (`&` `<` を含むワードも効く)。
- 「次のページ」の自由入力欄をやめて、ページ送り (`← 前の20件　1 2 [3] 4 5　次の20件 →`) にした。**存在するページにしか飛べない**:
  - 1ページ目は `index.html`、2ページ目以降は `index2.html` `index3.html`…とページ番号で名前を付ける。ファイルは最大でもページ数ぶん。
  - 1ページ目には「前の20件」が、最後のページには「次の20件」が出ない。現在のページは `[3]` のようにリンクにしない。スレッドが1ページ分しか無い板には、ページ送り自体を出さない。11ページ以上のときだけ、現在のページの前後を残して `…` で省く。
  - リンクは `amezo.cgi?folder=板&page=3` (GET)。押すと、そのページのファイルが新しければそのまま、古ければ (10秒) 作り直して `index3.html` へ転送する。範囲外の番号は最後のページになる。
  - 同じページは誰が頼んでも同じ内容なので、共有の `index2.html` のような上書きの取り違えは起きない。フォーム送信ではないので「再送信しますか」も出ない。10分たったファイルは掃除する。
  - 「◯番目から」の細かい位置指定はできない (20件区切り)。古い index に残っている `next=N` の欄は、そのページに読み替えて受ける。
- **投稿された URL は、署名つきの中継ページ (`/jump.cgi`) 経由のリンクになる** (下の「外部リンクの中継ページ」)。新規の投稿だけが対象で、既存のスレッドの直リンクはそのまま。
- 本文の URL のリンク化 (`linkify_urls()`) を作り直した。URL とみなすのは、`http://` か `https://` で始まり、ホスト名が英数字で始まり、URL に使える **ASCII の文字だけ** (と、エスケープされた `&amp;` `&#39;`)。
  直後の日本語 (`http://example.com見てね`)、`<…>` や `"…"` の閉じ側、末尾の `.` `,` `!` `?`、対応のない `)` `]`、末尾の `(` は URL に含めない。`http:evil` や `javascript:` はリンクにしない。
  href はエスケープを戻してから属性用にエスケープし直す (`&` は `&amp;`)。デコード済みの日本語を含む URL (`/wiki/PHP_(言語)` など) は、最初の日本語で切れる (アドレスバーからコピーした `%E6…` の形ならそのまま通る)。
- `AMEZO-NEXT` のコメントは出さない。
- 投稿行に `data-id` / `data-trip` と `ID:xxxxxxxx` が入る。新しいスレッドと index には `hide.js` を読む `<script>` が入る (既存スレッドには入らない)。
- スレッドの末尾だけを読むので、レス数が増えても投稿・再生成のメモリは増えない。管理画面も1行ずつ読んで出す (5000レスのスレッドでも `memory_limit=3M` で動く)。
- 管理画面は、同じ名前の `del` が1000個を超えて送られても欠けない (PHP の `$_POST` ではなく生の本文を読む)。
